# 批次接入裁决：全局复用 vs 本承运人范围内复用

裁决日期：2026-11-21
裁决事项：两家承运人提交内容相同的舱单，系统按文件内容认成同一批，后一家可看到前一家的批次、历史和下载物。

## 一、裁决结论

**拒绝全局复用，采用“只在本承运人范围内复用”（carrier-scoped reuse）。**

| 方案 | 结论 | 理由 |
|---|---|---|
| 按文件内容全局复用 | 否决 | 舱单内容只是数据，不代表归属。仅凭字节相同就让后一家看到前一家的批次、历史与导出，构成跨承运人越权；证据一旦混入他方批次，责任与封存口径无法切分。 |
| 完全不复用（每次新建） | 否决 | 相同舱单要重做全部核验，截单前必然积压，也违背“同输入同批号、只保留一条批次”的既有约定。 |
| **本承运人范围内复用** | **采纳** | 承运人编号并入批次指纹：不同承运人相同内容各自独立成批、互不可见；同一承运人重试相同内容仍命中同一条批次，核验结果直接复用，不新增第二条批次。兼顾隔离与截单时效。 |

## 二、接入口径（系统如何落地）

1. **身份来源**：请求头 `X-Carrier-Id`，或查询参数 `carrier_id`（两者等价，大小写规范化）；缺省为离线演示承运人 `DEMO-CARRIER`。非法编号返回 `400 BAD_CARRIER`，不静默落到默认承运人。
2. **指纹与批号**：批次指纹 `sha256` 的输入由 `承运人编号 + 源字节 + 核验上下文 + 规则版本` 组成（各段带长度前缀）。
   - 承运人不同 → 即使舱单字节完全相同，指纹、批号也不同，从根上不可能落到同一条批次。
   - 同一承运人、相同内容、相同规则版本 → 指纹相同，批号相同。
3. **存储唯一约束**：库表对 `(carrier, digest)` 建唯一索引，而非仅对 `digest` 唯一。写入用“存在即复用”，同一承运人重试不会产生第二条批次。
4. **所有访问路径强制带承运人条件**：批次详情、批次历史、复核、重跑、归档导出、HTML 页面一律 `WHERE carrier = 当前承运人`。
   - 跨承运人访问他方批次一律返回 `404 NOT_FOUND`（“批次不存在或不属于当前承运人”），不泄露该批次是否真实存在，避免存在性侧信道。
5. **旧库迁移**：隔离上线前已存在的历史批次无承运人列，连接时自动重建表并归入 `DEMO-CARRIER`，旧批不丢失、也不会被其他承运人读到。

## 三、批次接入结论（每次接入/复用随响应给出）

每个批次响应与导出包内均带 `accession` 结论，字段如下：

| 字段 | 含义 |
|---|---|
| `policy` | 固定 `carrier_scoped`，表明裁决口径 |
| `reused` | 本次是复用既有批次（true）还是新建（false） |
| `carrier_id` | 当前承运人编号 |
| `reused_run_id` | 复用时指向的批号；新建为 null |
| `reuse_of` | 复用来源说明：“本承运人上一次相同内容处理” |
| `evidence_owner` | 证据归属承运人 |
| `evidence_scope` | 证据范围声明：本批全部证据归属该承运人，其他承运人不可见、不可导出 |

### 复用了哪次处理

- 仅复用**当前承运人自己名下**、指纹完全一致的那一次处理（`reused_run_id` 明示批号）。
- 绝不复用其他承运人的任何处理；其他承运人的同内容舱单对当前承运人不可见。

### 哪些证据属于当前承运人

该批次下的全部证据均归属当前承运人，且只对其可见、可导出：

- 舱单采信记录与隔离项（含原始行号、原因码、源字节快照）
- 包装映射、拆并编组、危险品、净毛重、报关对账各模块核验视图
- 复核历史（revision/status）与版本封存结论
- 归档导出包 `manifest.json`、`evidence.json`（包内显式写入 `carrier_id`、`evidence_owner`、`evidence_scope`）

## 四、验收对照（需求逐条）

| 需求 | 落地与测试 |
|---|---|
| 跨承运人不能越权看到批次 | 详情/页面按承运人查询，跨方返回 404；`test_cross_carrier_cannot_read_detail`、`test_cross_carrier_html_page_blocked` |
| 跨承运人不能越权看到历史 | 历史接口按承运人过滤；`test_cross_carrier_cannot_read_history` |
| 跨承运人不能越权看到导出 | 导出接口先过承运人校验，包内标注归属；`test_cross_carrier_cannot_export` |
| 同一承运人重试相同内容不新增第二条批次 | `(carrier,digest)` 唯一 + 存在即复用；`test_same_carrier_retry_single_batch`、`test_cross_carrier_cannot_review_or_rerun` |
| 相同内容不同承运人独立成批 | 承运人并入指纹；`test_identical_manifest_cross_carrier_distinct_batches`、`test_manifest_carrier_bound_into_digest` |
| 写明复用了哪次处理、证据归属 | `accession` 结论 + 采信页“批次接入结论”面板 + 导出包归属字段 |
| 旧批次平滑过渡 | `test_legacy_rows_migrate_to_default_carrier` |

测试位于 `tests/test_carrier_isolation.py`，全套 `pytest -q` 通过。
